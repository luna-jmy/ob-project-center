- **组内分桶（用户明确要求）**：`splitByKind()` / `classifyProject()` 放进 grouping-service（业务规则，要能直接测）：`quick`（快速项目）→ `with-materials`（带资料）→ `plain`。**判定顺序即优先级：先判快速项目**——它没有自己的文件夹，不该因为所在目录里恰好有别的笔记而被算成带资料。带资料 → 各自独立框框；plain/quick → 两份紧凑列表（`.pm-project-row`，⚡ 标记快速项目）。单一桶非空时不显示桶标题（folder 模式下的常态），多桶才加标题。
- **避免标题重复**：folder 模式且分组内只有一个项目时，让该项目**直接顶上分组标题**（标题即项目链接 + 徽章），框内不再重复项目名。否则会出现「官网改版」标题下面又一个「官网改版」框框。值分组（objective/area）不合并——分组名（领域/目标）和项目名是两回事。
- **新增数据**：`GroupingResult.quickPaths`（快速项目路径集合，由 `isQuickProject()` 唯一口径判定：扫描根层 或 相对路径含标记段；越界按普通项目）与 `materialsByPath`（项目路径 → **它自己文件夹下**的资料，快速项目恒为空）。与 `NormalGroup.notes` 的区别写了注释：后者是分组维度（值分组是并集），前者是项目维度，用于框框/列表二分。抽出 `collectNotes()` 让两个维度共用「什么算资料」的口径（递归 + 剔除全部项目文档）。
- 清理：删除已死的 `.pm-card__toggle` / `.pm-card__body` / `.pm-card__key` / `.pm-card__badge` 等 CSS；操作按钮在紧凑行里**始终可见**（不靠 hover 才能触达，技能可访问性要求）。
